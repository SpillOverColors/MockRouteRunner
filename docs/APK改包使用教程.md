# APK 改包使用教程

核对日期：2026 年 11 月 12 日。适用于本项目的 Windows PowerShell 工具；不是任意 APK 通用修改器。

## 改包到底做什么

这套工具把自有步频模块通过 LSPatch 嵌入 APK 副本，使消费者进程里的步数传感器回调可以接收模块事件。基础路线模拟器不需要改包；需要接收增强步频的消费者才涉及这一步。

工具先根据 APK 内容寻找可能的适配路径，随后构建并签名副本。字符串识别只能说明“候选”，不能证明这个路径在运行中实际被使用。输出一个签名正确的 APK，也不能证明它能启动、能登录或能读到步频。

目前带模块的自有 StepDemo 已做事件实测。悦跑世界曾完成离线改包和签名核对，但目标读取尚未验证；步道乐跑尚无可信 APK 的完整适配验证。请不要把这份教程理解为两个校园跑 App 都已经兼容。

## 先保留原件，再准备环境

准备来源可信、版本明确的原 APK，另存一份，不要把它放在输出目录中。记录包名、版本号和 SHA-256。不要把已经修改过的 APK 当作原件，也不要把 APKS、XAPK 或安装包合集改个扩展名后交给脚本。

项目目录里有 `tools/patch_tool.ps1` 和 `.cmd`。还需要 Java、Android SDK 的 aapt2/apksigner、LSPatch JAR、已编译步频模块和自己持有的签名密钥。Java 17 可用于项目源码编译；本次 LSPatch JAR 需要能加载 class version 65 的运行环境，也就是 Java 21 或更新版本。本机使用 Android Studio 自带 JBR 运行成功。

公开源码包不应包含作者的签名私钥。自行构建后生成的密钥要自己保管；以后若要覆盖升级自己的改包版，需要继续使用同一密钥。丢失密钥后重新生成，不能恢复原来的升级签名。

查阅同包 BUILDING 文档完成本地工具链配置。当前审查过的旧脚本仍有本机构建路径，不能直接假定在另一台电脑解压就能运行。发布时若脚本已经增加环境变量支持，以随包《打包说明》的核对记录为准。发现脚本里残留他人的绝对 SDK 路径时，应先配置脚本，而不是创建同名用户目录。

## LSPatch 文件和许可证

本次使用的是 JingMatrix LSPatch v1.2 的 `lspatch-v1.2-487-release.jar`，核对过的 SHA-256 为：

```text
D238FDC414D121B7FA454D8B4CCF420DF3A8C97D563761861FF92BD9C5DA2165
```

从项目官方仓库的对应发布版本获取，并核对文件名和校验值：<https://github.com/JingMatrix/LSPatch>。对应版本源码入口为 <https://github.com/JingMatrix/LSPatch/tree/v1.2>。本地核对的该版本根目录许可证为 GPL-3.0；JAR 内的 Apache 组件声明不代表整个 LSPatch 都是 Apache 许可。

项目自有代码与 LSPatch 分别说明许可。带 LSPatch 的 StepDemo 改包产物也不能整体标作纯 MIT。公开再分发这类二进制前，需要准备与所用二进制对应的完整源码、构建资料及许可履行材料；仅放一个仓库链接不应被当作已经完成这些要求。本次公共源码包宜不附带第三方 JAR、带该运行时的改包 APK，也不分发校园跑 App 原包或改包。

## 执行改包

在项目根目录打开 PowerShell。先看脚本开头的参数，确认环境路径与当前电脑一致。下面展示已经核对过的参数形式，路径请换成自己实际的路径：

```powershell
.\tools\patch_tool.cmd -Apk "D:\APK输入\原始应用.apk" -OutDir "D:\APK输出\本次测试"
```

如果 Java 或密钥不在默认位置，可显式指定：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\tools\patch_tool.ps1" -Apk "D:\APK输入\原始应用.apk" -OutDir "D:\APK输出\本次测试" -Java "D:\Java\bin\java.exe" -Keystore "D:\私人密钥\debug.keystore"
```

这条示例使用脚本默认调试别名和默认调试口令，适合相应的本地调试密钥。自定义密钥时还需匹配 `-Alias`、`-StorePass`、`-KeyPass`。真实口令不要放进共享教程或截图；命令行参数仍可能进入命令历史或进程信息，脚本的日志脱敏并不消除这层暴露。

`-Module` 可指定模块 APK，`-Lspatch` 可指定 JAR。相对路径按项目根目录解释。含空格的路径必须加引号。建议每次使用新的空输出目录，既便于保存报告，也避免混淆旧产物。

`-Force` 不是解决失败的通用开关。当前脚本在复用输出目录时会移除旧的 `*-lspatched.apk`；不要把需要保留的文件放在该目录，也不要让输入 APK 位于其中。

若源代码包没有编译后的模块，应先按 BUILDING 文档构建 `tools/pedometer-module`。不要拿旧模块生成新包后，沿用新模块的测试结论。

## 读懂输出

输出目录会有报告、原件副本及成功时的 `*-lspatched.apk`。先读 `report.md` 和 `report.log`，核对输入版本、原件哈希、输出哈希、证书以及最终结果。

| 报告结果 | 含义和下一步 |
|---|---|
| `OFFLINE_PATCH_SIGNED_VERIFIED` | 本次离线改包和签名核验完成；还需要安装与消费者事件验证。 |
| `UNSUPPORTED_PEDOMETER_PATH` | 未找到当前工具可识别的候选路径，不能靠反复运行解决。 |
| `UNSUPPORTED_SPLIT` | 检测到分包依赖，当前单 APK 工具不处理。 |
| `ALREADY_PATCHED` | 检测到已有补丁，应重新取得可信原包。 |
| `PATCH_FAILED` | 修改过程失败，保留退出码和首段有效错误。 |
| `SIGNATURE_VERIFY_FAILED` | 输出不能通过签名核验，不要继续安装。 |
| 包名、版本或原件变化错误 | 停止使用本次输出，检查输入、目录和构建过程。 |

`CANDIDATE_ONLY` 的意思就是候选，不能改写成“已支持”。若输出报告缺失或出现多个无法区分的产物，先查清本次到底生成了什么。

## 安装前检查签名和数据

改包副本通常用自己的密钥签名，和官方安装版不同。Android 不允许把不同签名、相同包名的 APK 当作正常更新覆盖。本项目的改包工具也没有承诺自动生成可与官方并存的另一个包名。

安装前先列出需要保留的数据：路线原文件、应用内记录、账号登录方式、尚未同步的资料，以及恢复所需的官方安装来源。应用的系统备份可能受限制，不能把“按过备份按钮”当成已验证可恢复。无可恢复副本时，应保留官方安装版，只做离线研究或自有测试。

安装前先审核文件、签名及数据保留方案。对相同签名的自有测试包，可以在核对后安装；涉及官方 App 替换或数据丢失，先给出具体迁移方案再决定。不要为了让命令返回 Success 而卸载正式应用。

## 用 StepDemo 验证链路

先使用已经审核的带模块 StepDemo 测试版，授予身体活动权限并打开。路线模拟器中的目标包名填写 `io.github.dsh.stepdemo`，步频范围设为 100–130。先启动消费者，再启动控制器的模拟过程。

开始后检查消费者事件是否增长。暂停后留出一个短暂观察窗口，再比较两次读数，确认没有新增；继续后检查事件恢复；停止后再次比较两次读数。累计步数不是必须从 0 开始，停止也不要求归零。

连续样本中，每个 detector 事件代表一步；counter 则要结合累计值差和单调时间戳差计算。不能对相同时间的重复回调简单按次数计步。恢复后的第一个间隔可能横跨暂停，当前消费者会出现瞬时偏低读数，应单列解释，不能用它或界面中的模拟数值替代完整事件验证。

对其他目标 App，还需要分别证明它实际走了相应传感器路径。StepDemo 成功并不代表其他 App 成功；只看到模块已加载或握手就绪，也还不够。

## 连接失败时按顺序排查

先查消费者是否启动、是否授予身体活动权限、是否安装了正确的改包版本；再查控制器包名和模块版本。当前控制通道端口由包名派生，范围是 39000–39999，不再固定使用旧版 38999。

端口散列可能碰撞；当前仅支持预期的主进程消费者，其他进程里的传感器订阅不能直接套用主进程结论。`AUTH` 和 `HELLO` 是协作与就绪检查，公开共享口令不是安全隔离手段。

电脑端调试连接有短超时，不能在一个空闲连接里等很久再发命令；跨暂停观察窗口时应重新连接并握手。正常用户应优先用路线模拟器的按钮控制，而不是手工发协议命令。

如果 App 启动崩溃、无法登录或没有事件，先停止本次测试并保留错误。不要据此直接转向 root、修改系统验证或重复覆盖安装。

## 恢复原版与公开分享

先停止控制器，确认步频测试不再产生新增事件，再处理应用切换。若原版与改包版包名相同而签名不同，回到原版也不是一次普通覆盖更新；仍需先确认数据恢复方案。只改包而未安装时，原设备上的官方应用不会因此发生变化。

分享项目时，分享干净的自有源码、教程、构建脚本、示例和许可证。不要附带自己的 keystore、生产口令、设备日志或学校 App APK。收到别人提供的源码后重新构建，会得到自己的签名；它不应被描述为作者签名 APK 的可直接升级包。
