# 从零开始：路线模拟器、悦跑世界与步道乐跑

这份教程对应正式版1.3.1。页面按“选择路线、设置本次运动、运行控制、实时状态”排列，高级设置和日志默认收起。首次操作只需要一台Android设备、主APK和自己的路线文件。

## 1. 先安装主软件

将 `MockRouteRunner-1.3.1.apk` 复制到设备，在文件管理器中打开，按系统提示允许这个文件管理器安装应用。只授予安装来源所需权限，不需要关闭全局安全检查。安装完成后，主屏显示“路线模拟器”。

已有 `MockRouteRunner Sandbox8` 的用户：本版保留相同包名和签名，系统应提示更新，应用内路线与断点通常保留。更新前请结束本次运行并保留原路线文件。若提示签名冲突或无法更新，先停止，不要卸载来强行安装。

曾安装旧 `io.github.dsh.mockroute` 或 `acceptance` 的用户：它们与本版包名不同，不会自动迁移数据。不要让多个版本同时运行，开发者选项也必须选中本次实际使用的版本。

主软件不需要高德Key。AMapDiag只是开发阶段的对照工具，不需要一并安装。

## 2. 打开开发者选项，选择模拟位置应用

打开系统设置，在“关于手机/关于平板”中找到版本号，连续点击直到系统提示开发者模式已开启；若要求设备锁屏验证，由你自己完成。Android通用说明是点击版本号七次，小米/HyperOS的入口名称可能是“OS版本”或“全部参数与信息”。

回到设置，搜索“开发者选项”，小米常见路径是“更多设置 → 开发者选项”。开启总开关，找到“选择模拟位置信息应用”，选择“路线模拟器”。它是选择某个应用的列表，不是给步道或悦跑选择定位来源。

系统“位置/定位服务”总开关也要打开。正常使用不需要连接电脑，不需要USB调试，也不需要打开所有开发者开关。“强制启用完整GNSS测量数据”不是必要条件。

应用请求位置时允许精确位置。Android13及以上建议允许通知，这样能看到运行状态并从通知停止。目标校园跑软件自己请求位置、后台位置、活动识别时，按其实际需要在系统页面授予；这些权限属于目标应用，主工具不能替它获取。

官方开发者选项说明：[Android Developers](https://developer.android.com/studio/debug/dev-options)。不同厂商界面以实际设备为准。

## 3. 小米/HyperOS先处理后台限制

长按路线模拟器图标，进入“应用信息”，找到“耗电详情/电池 → 省电策略”，选择“无限制/不采取任何限制措施”。新版主屏的“后台运行设置”会打开本应用的信息页，之后仍需手动找到省电策略。

请确认页面显示的是当前实际运行的包，而不是另一个测试版本。若系统提供后台自启动选项，可按需要允许；运行期间不要使用一键清理或强行停止。把应用锁在最近任务中只能作为辅助，不替代无限制设置。

之前的测试曾在长时间运行时丢失前台服务，目标随后提示GPS关闭。通知还在、注入次数仍增加，才说明当前工具仍在工作；“有前台服务”并不保证厂商不会限制它。系统后台限制参考：[Android Developers](https://developer.android.com/topic/performance/background-optimization)。

## 4. 准备能读取的路线

把路线放到设备“下载/Download”目录。可以是 `.gpx`、包含GPX轨迹的 `.xml` 或 `.json`。导入时点“导入 GPX / XML”或“导入 JSON”，两个入口都通过系统文件选择器并按内容识别；不要只把其他格式改后缀。

GPX应有 `trkseg/trkpt` 或 `rte/rtept`，坐标为WGS84。JSON点顺序是 `[纬度, 经度]`，不要颠倒。高德地图拾取点通常涉及GCJ-02坐标，不能直接把未经确认的坐标当WGS84使用。

导入后检查路线摘要：点数、长度、开放或闭环是否符合预期。单圈不必等于本次总距离，闭环会反复循环。单条开放折线会到端点折返。多条闭环需在同一个路口衔接，不支持把相隔很远的轨迹段随意拼起来。

仓库 `examples/` 有合成结构示例和北大约5km的地图示例。它们用于理解格式，地图示例不等于现实道路全部开放。自己的私有路线自行保留，不要误上传公开仓库。

## 5. 编辑经纬度点

点“编辑路线点”，先选对应路线，再点击列表里的点，使用新增、编辑、删除、上移、下移。开放折线可以编辑两端；闭环的共享路口单独设置。完成后点保存，取消则放弃本次编辑。

编辑器没有底图，不会检查点之间是否有围墙、建筑或可通行道路。不要在运行中改路线；已有磁盘断点时，先完成或清理旧会话再换路线，避免旧断点引用后来更换的路线。当前没有对外导出按钮，原始文件务必自行留底。

## 6. 参数怎样填

总距离单位是米。例如2km填2000，5.5km填5500，11km填11000。点击总距离会全选文本，直接输入新值；离开输入框后再检查，避免把新数字接在旧数字后面。

| 参数 | 常用示例 | 单位与含义 |
|---|---|---|
| 最快配速 | 390 | 秒/公里，即6分30秒 |
| 最慢配速 | 470 | 秒/公里，即7分50秒 |
| 总距离 | 5500 | 米；不是单圈长度 |
| 程序步频下限/上限 | 100 / 130 | 步/分；不代表目标已读取 |
| 位置扰动上限 | 0.3 | 米；允许0–0.5 |

允许配速180–600秒/公里，最快数值不得大于最慢。步频1–300，下限不得大于上限。总距离须为有限正数。参数由你决定，不按某个学校硬编码。

高级区域中的“目标包名”只供已经适配的步频桥接使用；单纯定位可以清空。填写包名不会自动改包、安装模块或让目标读取步频。

## 7. 共同的启动顺序

先结束目标应用上一次记录，并从系统应用信息停止其旧进程；不要清除数据。停止其他模拟定位软件，只保留本次路线模拟器。

在路线模拟器点“开始模拟”，阅读并确认其他模拟工具已经停止。等状态显示“运行中”，检查三个地方：目标距离是本次输入值；注入次数持续增加；坐标已到导入路线附近。刚开始只有Toast提示并不能证明启动成功，失败原因会显示在状态和日志中。

**确认工具已运行后，再打开目标应用。** 这一步很关键：本机步道定位打通的实际顺序是先创建并稳定输出模拟位置，再冷启动目标。目标已初始化却一直停在旧位置时，不要急着增加距离或延长测试，应先结束旧流程，再按这个顺序重试。

工具从点开始起就会移动。切换目标应用、处理权限和进入跑步页面期间已经走过的距离，不会自动记到目标会话中。目标实际累计和控制器累计可能不同；本软件不会自动同步双方的起终点，也不会自动按目标距离延长运行。需要对照时预留足够时间，并以目标自己的记录为准。

## 8. 悦跑世界：选择系统定位服务

在本次测试的悦跑世界1.1.23中，进入“我的 → 设置/个人设置 → 定位源”，选择“系统定位服务”，点保存。不要与同页“更改定位方式”等入口混淆；不同版本名称可能变化，以实际菜单为准。

完成设置后先退出旧运行流程。按照上一节先启动路线模拟器，检查其运行状态，再重新打开悦跑世界。进入运动页面，先看蓝点是否到达路线并连续变化，然后由你点击目标应用自己的开始按钮。

过程里看目标自己的轨迹和距离；路线模拟器显示的配速是程序值，目标会重新计算，短时有差异不等于完全失败。本机实测悦跑世界沿跑道实际累计超过4km，用户确认效果符合预期。

结束时先按悦跑世界自己的暂停/结束流程处理记录，然后回到工具停止清理。如果工具先达到总距离并停止，目标可能提示GPS丢失；这不等于目标记录已经自动结束或保存。

## 9. 步道乐跑：先注入，再打开

本机测试的是步道乐跑4.3.3。未找到像悦跑那样公开可切换的“系统定位服务”选项，不需要去寻找不存在的同名开关。

先确认目标位置权限和需要的后台权限。结束目标旧进程，启动路线模拟器并检查实际目标距离、注入次数和位置，再打开步道。进入学校配置下可用的自由跑/乐跑入口，先确认地图位置已到路线附近且发生变化，再开始目标的记录。

本机曾仍提示“GPS信号弱”，但位置连续变化、距离实际累计。因此不能只看这行提示；也不能在地图停在全国或距离始终0时宣称成功。本机单次记录超过10km，最终汇报10.37km并上传成功。

打卡点、校区范围、时间段、人脸或其他学校规则由目标应用决定。路线模拟器不自动处理这些流程，也不保证记录符合任何学校规则。长时间运行时重点检查工具通知和实际状态，避免系统省电结束后台服务。

结束记录由你在步道中操作，确认其保存/上传结果；工具不会代为提交。随后停止模拟并清理。

## 10. 暂停、继续与结束

“暂停并保存”暂停工具并写入断点；“继续断点”继续同一工具状态，不补算暂停期间的时间和距离。它不会自动暂停或恢复另一个App，因此需要时两边分别操作。

应用被结束后，只有此前成功保存的磁盘断点能继续；不是每秒自动存档。磁盘继续使用旧会话保存的总距离和参数，不采用你刚填的新参数。要新开一次，检查参数后用“开始模拟”。

“停止并清理”及达到总距离都会清理本次provider并清除本次可继续断点。程序不会自动重启或自动重开目标记录。清理失败时查看日志并先停止测试，不要让多个模拟器互相替换provider。

结束测试后，可在开发者选项将模拟位置应用改为“无”。若其他地图仍显示旧点，关闭测试工具，重新打开真实定位应用等待新结果；必要时重启设备，不要为清理而卸载校园跑软件。

## 11. 遇到问题先按这个顺序检查

| 现象 | 先做什么 |
|---|---|
| 输入11000却只跑2000 | 重新全选总距离，确认输入；开始后检查实时状态中的目标值，不以旧截图判断 |
| 已运行但目标在旧位置 | 先确认注入次数和坐标，再结束目标旧进程，保持注入并重新打开；悦跑检查定位源 |
| 目标始终0km | 地图位置是否连续更新？是否真的点击目标开始？不要把系统回调当作业务已累计 |
| 途中提示GPS关闭 | 检查工具是否已到总距离、服务是否还在、实际包是否无限制；不要直接认定崩溃 |
| 导入失败 | 检查内容结构、WGS84及经纬顺序；XML必须是支持的GPX轨迹结构 |
| 提示最近有mock位置 | 先停止其他模拟器，检查模拟位置选择；不要盲目反复启动覆盖 |
| 安装签名冲突 | 停止安装并保留数据，核对包名、版本和签名，不直接卸载 |
| 步频不被目标读取 | 主界面只是计算值；没有目标侧实证时不能靠填包名解决 |

## 12. 与源码对应的范围

导入与识别：`RouteStore.java`、`RouteModel.java`；运动：`MotionSimulator.java`；系统注入与停止：`MockRouteService.java`；断点：`RunCheckpoint.java`；界面：`MainActivity.java`及`activity_main.xml`；可选步频桥：`PedometerBridge.java`。

这份教程不假定软件有自动提交、自动启动目标、任意XML导入、地图规划或普遍免改包步频等源码没有实现的功能。
